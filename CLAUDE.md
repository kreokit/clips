# KreoKit Clips: build spec for Claude Code

Read this before every task. It is the source of truth for scope and architecture.
**Status (2026-10-21):** Milestones 1 (Scaffold), 2 (Transcribe long videos) and 3 (moment finder + clips board, with platform presets) are done and tested. Milestone 4 (Reframe) started 2026-10-21 (the user said go; decisions under "Reframe").
App #3 of the KreoKit suite. App #1 is KreoKit Captions (`kreokit/captions`), app #2 is KreoKit Cutout (`kreokit/cutout`). Reuse both wherever possible.

## What we are building

A cross-platform desktop app that turns a long video (podcast, interview, talk, livestream) into **vertical short clips with captions**, fully offline:
import long video → transcribe → find the best moments → review and adjust clips → reframe to 9:16 (follow the speaker) → styled captions → export all clips.

Target users: creators worldwide who repurpose long content for TikTok, Reels and Shorts. English-first.

## Hard rules (same as the other apps)

- **No proprietary code or assets.** Build only from public docs, open-source libraries and observed behaviour. Never copy another product's name, logo, icons or exact UI.
- **Offline first.** No servers, no accounts, no telemetry, no cloud AI APIs. The only network calls are one-time model downloads from our own mirror releases.
- **Licences must stay MIT/Apache-compatible, including model weights.** Only MIT / Apache-2.0 / BSD weights. Verify every model's license from its official source before adding it; never use non-commercial or research-only weights. Record everything in `THIRD-PARTY-LICENSES.md`. Mirror model files in `models-vN` releases on `kreokit/clips` (never change a published one) with license + SOURCE.md + SHA256SUMS.
- Every commit builds and passes `cargo test` and `pnpm test` on its own. Small topic-based commits.
- Only screenshot the KreoKit window, never the full screen.
- Fixtures: only our own or free-licensed videos (Pexels/Pixabay, license noted per file), or synthetic ones (macOS `say` + ffmpeg test patterns).

## Lessons from Captions and Cutout (must follow)

- **Release builds use a newer macOS SDK than dev builds.** Weak imports can crash on older macOS. Run `check_macos_binary.py` (copy from Cutout, with its two documented allow-listed symbols) on every macOS release build.
- **whisper.cpp on macOS:** build with `-UACCELERATE_NEW_LAPACK -UACCELERATE_LAPACK_ILP64` (classic Accelerate `cblas_sgemm`), exactly as Captions does. Never the macOS 13.3+ variant.
- **ONNX Runtime:** `ort` 2.0.0-rc.10 + ONNX Runtime 1.22 static, pinned for Intel Mac / macOS 12 support, exactly as Cutout does.
- **FFmpeg:** LGPL-only sidecars (no libx264/libx265, no GPL), built and checked exactly as Captions does.
- Release workflow: build → all checks (bundle, licenses, macOS binary check, `--self-test`) → upload only if everything passed → draft pre-release.
- Dev port: use **1440** (Captions 1420, Cutout 1430).

## Stack

- Tauri 2 (Rust) + React + TypeScript + Vite, pnpm
- whisper-rs (Whisper), `ort` (ONNX Runtime) for face detection, FFmpeg sidecar for decode/encode
- No LLM in v0.1 (see "Moment finder")

## Core pipeline

1. **Probe + audio extract** (ffmpeg).
2. **Transcribe** the whole video with word timings (chunked for long videos, progress + cancel, resumable cache per video).
3. **Moment finder** proposes candidate clips (default TikTok Rewards 61–90 s; Shorts / Reels 20–60 s).
4. **User review:** keep/discard candidates, adjust in/out points on the timeline, add manual clips.
5. **Reframe** each clip to 9:16: detect faces on sampled frames, build a smoothed crop path that follows the active speaker; fallback center crop; manual override.
6. **Captions** per clip using Captions' styles (positions relative to the 9:16 frame).
7. **Export** all clips: 1080×1920 MP4 with burned-in captions, plus optional SRT per clip.

## Moment finder (v0.1: transparent heuristics, no LLM)

Score candidate windows built from sentence/pause boundaries (never cut mid-sentence):
- Self-contained: starts at a sentence start, ends at a sentence end, minimal dangling references at the start ("and", "so", "but", "that").
- Hook strength in the first 3 s: questions, numbers, strong statements, "the secret/mistake/truth is…", direct address ("you").
- Energy: speech rate and audio loudness relative to the video's average; laughter/applause tags.
- Length fit to the target duration.
Show the score breakdown in the UI ("why this clip"), so users trust it and can sort/filter. Keep the scoring in one pure, unit-tested Rust module. (Backlog: optional local LLM ranking with a permissively licensed model.)

## Reframe

- **Face model (decided 2026-10-19): MediaPipe BlazeFace full-range** (Apache-2.0, clean training data). It ships as TFLite; in M4 convert it to ONNX in a GitHub Actions workflow (reproducible, pinned tool versions, checked against the TFLite output, like Cutout's "Export BiRefNet"), then mirror it in `models-v2` (`models-v1` holds the Whisper models and is never changed) with licence, SOURCE.md and SHA256SUMS. Still verify the licence from the official source and record it in `THIRD-PARTY-LICENSES.md` when adding it.
- **Excluded face models:** YuNet, SCRFD and YOLO-face (training-data / licence risk). Don't revisit without asking.
- Sample ~2–5 fps, track faces, pick the active speaker (largest/most central face, or the face whose mouth region moves while that segment is spoken when feasible).
- Smooth the crop path (no jitter; limit speed; hold position during short gaps), keep the face in the upper-middle third.
- Fallbacks: center crop, or "fit with blurred background" (letterbox inside 9:16).
- Manual override: drag the crop window on a keyframe.
- **Decided 2026-10-21 (user, M4 plan):**
  - Speaker: the biggest / most central face, switching only with hysteresis (a new speaker holds ≥ 2 s). Mouth movement is a time-boxed, measured experiment on the two-face fixture: if it doesn't clearly beat the simple rule, it stays on a branch (like Cutout's guided-filter experiment).
  - Speaker change and camera cuts: **cut, never pan**.
  - **No zoom in v0.1:** the crop is the full source height at 9:16, moving only sideways. A source under 1080 px tall shows a small note in the editor: "Low-resolution source; the vertical clip will look soft". Backlog: zoom, split screen for two speakers.
  - Face analysis runs in the background for kept clips and immediately for the clip open in the editor; **never at the same time as transcription**, and it stops when the app closes.
  - Fixtures: found on Pexels/Pixabay, small files, licence + source URL per file in `fixtures/LICENSES.md`; no people from movies/TV/YouTube.
  - Stop after step 1 (model licence check + conversion `report.md`) for the user's OK before publishing `models-v2`. **`models-v2` must not be marked "latest"** (app releases stay latest). Push after each step.

Missed: the small, turned-away face in `studio-wide-small-faces.jpg` (a portrait photo letterboxed into 192 px; small faces in wide 16:9 frames may need tiling, measure in step 3).

After publishing any release, check `gh release list` and restore the badge.
- **ONNX Runtime + face model (M4 step 2):** `ort` =2.0.0-rc.10 with Cutout's features (ONNX Runtime 1.22 static; `check_macos_binary.py` comes with the release workflow in M6). `models.rs`: `MirrorFile` (release, name, size, SHA-256) for every downloadable file; `WhisperModel::file()` (`models-v1`) and `FACE_MODEL` (`models-v2`); `download(file, models_dir, …)` writes `<name>.part` and renames after the checksum. `faces.rs`: `Detector::load` (Level3, one intra-op thread) checks the model's tensor names and shapes (`input` [1,192,192,3]; `reshaped_regressor_face_4` [1,2304,16]; `reshaped_classifier_face_4` [1,2304,1]). Downloaded from `models-v2` and loaded on the dev Mac (macOS 12, Intel) 2026-10-21. Licences in the app: `src-tauri/resources/licenses/` (bundled as `licenses/`): ONNX Runtime's LICENSE + ThirdPartyNotices (copied from Cutout, same version) and `MODEL-BLAZEFACE-LICENSE.txt`. `ort-sys` pulls build-time-only crates (openssl, tar, native-tls) to download ONNX Runtime; all on the allow list.
- **Frames (M4 step 4, `frames.rs`):** `sample(video, display size, from, to, cancel, on_frame(t_ms, Rgb))` streams rgb24 frames from FFmpeg at 4 per second, long side ≤ 640 (`sample_size`, never upscaled, even sides; FFmpeg's default autorotation gives the display orientation). Sample k of a run from T is the picture on screen at T + 250k ms on the container clock (the player's and the transcript's): `-ss T … fps=4:start_time=0:round=up`. **`round=up` matters:** the default `round=near` puts the last frame rounding to a slot there, up to 125 ms late (measured 0.12 s on a moving square). A picture starting after the sound holds its first frame until it starts (tested with `-itsoffset 0.5`). `Histogram` (16 bins per channel) `distance` 0–1 for camera cuts: a red→blue cut scores 0.67, a quarter of the frame changing < 0.1; the cut threshold is tuned with the tracker (step 6). Tests use lavfi sources only (FFmpeg 4.4 compatible).
- **Reframe fixtures (M4 step 5, `fixtures/reframe/`, `scripts/make_reframe_fixtures.py`):** synthetic `moving-face` (12 s: hold, slide, ±6 px sway, cut at 8 s to another face and background, no face 10.0–10.5 s) and `two-faces` (10 s: A bigger; B bigger only 2–3 s; cut at 5 s, then B bigger), each with a `.json` of the true boxes per 250 ms sample (at the frame on screen then); real Pexels `podcast-wide` (two people in profile at microphones, faces ~10% of the height, 20 s) and `talking-head` (one person, 12 s), both silent originals. All 640×360, ~0.5 MB together, silent AAC tracks so the app imports them. Detector on them (`finds_the_synthetic_faces`, `real_clip_faces`): synthetic 45/45 and 80/80 faces, worst IoU 0.79, nothing extra; podcast-wide has a face in every sample but both people in only 45 of 80 (the second is found by the whole-frame pass or not at all, since the tiles run only on empty frames); talking-head 48/48. **The real clips have no sound**, so who is speaking there can only be read from the picture (matters for the mouth-movement experiment).
- **Cuts (M4 step 6, `frames.rs`):** `Look` (colour `Histogram` + 32×18 brightness `Thumbnail`); `is_cut_from`: thumbnail distance > 0.12 or histogram > 0.3. Measured on the fixtures (`cut_distances`): cuts 0.23–0.39 thumbnail; a big face popping in or out 0.15 (counts as a cut, harmlessly); a face growing 0.09; sliding 0.02; real clips without cuts ≤ 0.002. The histogram alone missed the two-faces cut (0.17 < a face vanishing, 0.21). A real cut between the two Pexels clips is found at exactly its time (`a_real_cut_is_found`).
- **Tracks and subject (M4 step 6, `tracks.rs`, pure):** shots split at cuts; within a shot, faces linked to tracks seen in the last 1 s (IoU, or centre within a face width × (1 + seconds unseen), best pairs first); gaps ≤ 1 s bridged by interpolation (`Subject.seen` false there). Subject: `worth` = face height / frame height × up to 1.25 when centred, averaged over ±0.5 s (±1 s cut a real 3 s lead below the hold time); only tracks seen ≥ 3 times; another face takes over when 1.15× better for 2 s, moved back to when its lead began (offline); a lost subject hands over at once; a lead still under 2 s when the shot ends doesn't switch; a cut starts over. Fixtures: synthetic subjects right on every sample; podcast-wide 2 tracks, 1 change (at 14.5 s, the other person's face grows); talking-head 1 track.
- **Crop path (M4 step 7, `reframe.rs`, pure):** `crop_size` (full height at 9:16; sources taller than 9:16 get the full width and move up/down with the face 38% down the crop), `auto_path(samples, subjects, source size, frame size)` → `Path { axis, crop, keyframes, no_face }`. Segments split at cuts and subject changes; the crop **jumps** there, unless the new framing is within the dead zone of the old (no micro-jumps). Within a segment: 5-sample median, dead zone ±15% of the crop width (holds still), a move once the face has been outside for 0.5 s, **starting when the face began to move** (offline), to the median of the next second, **eased with smootherstep** (zero speed and acceleration at both ends) at ≤ 0.4 source widths/s (0.3 let a fast slide half out of the crop). `Keyframe { t_ms, pos, jump, ease }`: `position_at` joins keyframes linearly, along smootherstep into an `ease` one, not at all into a `jump` one (preview and export must draw the same). Faceless stretches hold the last position; a faceless segment under 2 s keeps the crop (else centred); no face in the whole clip → centre + `no_face`. Fixtures end to end: every true face fully inside the crop on every sample, top speed 0.40, jerk ≤ 5.4 widths/s³ (measured on even 40 ms steps; 33.3 ms rounded to whole ms adds noise); podcast-wide 1 jump (the subject change at 14.5 s), talking-head holds still. **Mouth-movement experiment (2026-10-21): not measurable, not built.** The synthetic two-face fixture has still mouths, the Pexels clips have no sound (no truth for who speaks), and at 640×360 a mouth is ~12 px; it needs a free-licensed two-person clip with sound at ≥ 720p (backlog).
- **Face analysis job (M4 step 8, `analysis.rs`, commands in `lib.rs`):** cache `<project>/faces/` (`projects::FACES_DIR`): `meta.json` (cache version, face model SHA-256, sample size, step, video size + mtime; any change discards the folder) and `block-NNNNN.json` per 10 s of video (`tracks::Sample`s), written atomically when complete; a run decodes consecutive missing blocks with one FFmpeg process starting one sample early (cut flag at the block edge), so Cancel loses at most a block. Tested: cached samples equal a straight analysis (cut flags included); cancel after block 1 keeps it and the resume does only block 2; nothing to do → the model isn't loaded. Commands: `analyze_faces(id, ranges)` (downloads the face model if missing; `faces-progress {id, done, total}` in blocks; errors `"transcribing"` while a transcription runs, `"cancelled"` when stopped), `cancel_faces`, `reframe_path(id, in, out)` → `Option<reframe::Path>` (`None` until analysed; tracks and subject chosen within the clip). **Never beside a transcription:** `analyze_faces` refuses while `Busy`; `transcribe` cancels a running analysis and waits for it (up to 30 s) before starting. Both keep the computer awake. **Quitting** (`RunEvent::Exit`) sets both Cancel flags; an FFmpeg still writing then dies on the closed pipe.
- **Clip framing (M4 step 9):** `Clip.framing = { mode: track | center | fit_blur | manual, manual: [Keyframe] }` (`projects::Framing`, `CropMode`; TS `Framing`, `defaultFraming()` in `clips.ts`). `#[serde(default)]`: clips saved before M4 follow the face. Manual keyframes are on the video's clock (those outside the clip are ignored) and move with in/out points when `shift_clips` upgrades an old transcript. The automatic path is not saved; it comes from the face cache (`reframe_path`).
- **Editor framing (M4 step 10):** `ClipEditor.tsx` shows a **9:16 preview**: the one `<video>` sized and shifted inside a 9:16 box each frame (`cropPlacement`, `lib/reframe.ts`), so no rendering; Fit + blur fits the video and draws a 54×96 copy of the frame behind it, blurred by CSS (video content, not UI chrome). `FramingPanel.tsx`: mode (Follow face / Center / Fit + blur / Manual), a 16:9 overview with the crop outlined (lime: the active indicator); dragging the crop sets a point at the playhead and switches to Manual, starting from the automatic path (`seedManual`); new points are eased in (`setKeyframe`, a point within 150 ms is moved instead); "Remove point", "Back to Follow face"; points show as diamonds on the clip's track. Status: "Finding faces…" with progress, "Faces are found once the transcription has finished", errors with Try again, "No face found, using center crop" + "Use Fit + blur", and the low-resolution note (short side < 1080). `lib/reframe.ts` mirrors `position_at`/`ease`, checked against the same `fixtures/reframe/path-cases.json` as Rust. `lib/faceQueue.ts` (+ `faces.ts` `faceQueue`, `useCropPath`): one queue; the editor's clip is "now" and pre-empts background jobs (requeued); `"transcribing"` waits and retries (at once when a transcription ends, `transcription.ts`); leaving a project drops its jobs. **WebKit quirks (macOS 12):** right after a load, `seeked` fires while `currentTime` still reads 0, then it settles without another event (re-read on `loadeddata`/`canplay`; the M3 editor could sit at 0 until playback); drawing a just-sought frame into a canvas can give black and there is no `requestVideoFrameCallback`, so the overview redraws 0.1/0.3/0.7/1.5 s after a seek. Checked in the app on the Goggins project (720p: the note shows), with Follow face, Fit + blur and Manual.
- **Small faces (decided 2026-10-21, user):** in step 3, measure detection on wide video frames. If faces under ~8% of the frame height are missed, add a two-halves (overlapping tiles) pass, **only for frames where the full-frame pass finds nothing**. Still no face → the clip falls back to Center and the editor shows "No face found, using center crop" (so the user can switch to Fit + blur).
- **Detector (M4 step 3, `faces.rs`):** `Detector::detect(Rgb)` → `Vec<Face>` in frame pixels (score, box, six keypoints, `MOUTH` = 3), best first. Fitting is a separable triangle filter (PIL's "bilinear", widening with the scale), centred, black padding; decoding and weighted NMS as in the export script. Matches `fixtures/faces/reference.json` (Python + PIL): IoU 0.97–1.00, scores within 0.008, mouth within 0.7% of the face height (`matches_the_export_reference`, ignored; CI runs it). **Small faces measured** (`small_faces_on_wide_frames`, real faces pasted into 640×360 frames, 18 per size): the whole frame finds 0/18 at 6%, 1/18 at 8%, 9/18 at 10%, 16/18 at 12%, all from 15% of the frame height; **with the two-tile pass (only when the whole frame found nothing) all from 8%**, 17/18 at 7%, 13/18 at 6%, none under 5%. Tiles: two squares (side = short side) at both ends of the long side, for frames ≥ 1.5:1 (not 4:3); merged by weighted NMS. ~7.5 ms per 640×360 frame, ~15 ms more when the tiles run (dev Mac, one thread, release build). The studio photo's turned, small face scores 0.61 (threshold 0.6): faint faces flicker in and out, which the tracker (step 6) must bridge.

## Projects (decided 2026-10-19)

- **Auto-saved, no Save dialog.** Each imported video gets a project in the app data folder (`<app data>/projects/<id>/project.json`, plus its caches: transcript, candidates, face tracks). Every change is saved automatically (debounced, atomic temp file + rename, as Captions' `project.rs`); there is no Save / Save As.
- The project id is a hash of the video path + size + mtime, so importing the same video again opens its project. A file at the same path whose size/time changed (rewritten, re-exported, touched) reopens that path's project, refreshed (size, time, probe), instead of a second one; empty duplicates left by earlier versions (no clips, no transcript) are removed then (fixed 2026-10-21: Home showed two "hello" after the fixture was regenerated). Recent projects on Home come from this folder; a missing video shows "Locate video…".
- **Delete project** (decided 2026-10-21, user): the ⋯ on each Home card (and right-click) and the project's ⋯ menu; the dialog says "Delete this project? Your video file is not touched." Deletes the project folder, never the video. Its transcript folder moves to `projects/kept-transcripts/<id>` (the id a new project of the same video gets); opening the video again makes a fresh project that takes it back with its settings, so it isn't transcribed again. **Transcribe again** (project ⋯ menu) deletes the transcript (`discard_transcript`); clips stay and are rescored when the new one is done.

## Transcription (milestone 2)

- **Models** (`models.rs`): Base / Small / Large-v3-turbo from our `models-v1` mirror only (made by the manual "Mirror Whisper models" workflow: HF revision, sizes and SHA-256 pinned), stored in `<app data>/models`. A same-sized file in Captions' sibling folder (`…/com.kreokit.captions/models`) is used in place, read-only, after a SHA-256 check that is remembered in `shared-checked.json` while its size and mtime stay the same. `prepare_model` checks or downloads (`model-progress` events); `cancel` stops it
- **Engine** (`transcribe.rs`): Captions' pipeline unchanged (DTW word timings, edge refinement, sound-tag filter, custom-words prompt), split into `Engine::load` (once per run) and `Engine::transcribe` (per part). `wer.rs` from Captions (tests only until the M6 self-test)
- **Audio** (`audio.rs`): streamed from ffmpeg as 16 kHz f32 through a pipe, never fully in memory, no WAV on disk; a loudness level per second (dBFS) for M3. **Sample 0 is the video's 0:00** (`aresample=async=1:first_pts=0`): audio that starts after the picture (phone/screen recordings, edited exports; `VideoInfo.audio_start_ms`) is padded with silence; before 2026-10-21 that gap was dropped and every word was early by it in the player. Cache version 2; version-1 caches are upgraded when a project opens (`transcription::upgrade`): probed once, a finished transcript + loudness + the project's clips move by `audio_start_ms` when it's ≥ 20 ms, an unfinished run starts over, in-sync videos keep their times
- **Parts** (`chunks.rs`): cut in the middle of the longest pause between 4:30 and 5:30 (nearest 5:00 on a tie), else at 5:00, judged only from audio since the part's start. The first run reads the whole audio once ("Reading the audio") to make the plan (all cuts + loudness, `plan.json`), so the part count is exact and later runs seek (`AudioStream::open_at`, ffmpeg `-ss`) straight to where they resume. Silent parts skip Whisper (it invents "Thank you." for silence)
- **Checkpoints inside a part:** whisper.cpp's progress callback runs at the start of each 30-second window, when earlier segments (and their DTW times) are final; `transcribe.rs` reads them there through whisper-rs-sys (the new-segment callback is unreliable with DTW on) and the job saves them as `part-NNN.partial.json` (done_ms, language, segments). A resume opens the audio at done_ms with the saved text as the prompt, so Cancel loses at most ~30 s. `transcript_status` reports `saved_until_ms`; the UI shows "Resume from 3:40" / "Saved up to 3:40 of 10:32" / "Nothing saved yet"
- **Job** (`transcription.rs`): `<project>/transcript/` holds `meta.json` (settings, video size + mtime, part limits; any change discards the folder), `plan.json`, `part-NNN.json` written as each part finishes (resume = skip them) plus the current part's checkpoint, and at the end `transcript.json` + `loudness.json` (part, checkpoint and plan files removed). The model loads only if a part needs it. Language detected on the first part with sound, then fixed; each prompt is the custom words + the previous part's last 30 words. Times are clamped into their part and never go backwards. Progress: position, part of ~N, ETA from the measured speed (shown after 5 s of audio)
- **Commands**: `transcript_status(id, settings)` (finished transcript, or finished parts for Resume), `transcribe(id, settings)` (one at a time, `transcription-progress` events). Settings live in `project.transcription` (`#[serde(default)]`; Base in dev, Small in releases); the frontend trims custom words before sending (`normalized`), so stray spaces don't discard a cache
- **Keep awake** (`awake.rs`): while `transcribe` runs, an IOKit `PreventUserIdleSystemSleep` assertion on macOS ("KreoKit Clips: transcribing" in `pmset -g assertions`), `SetThreadExecutionState` on Windows; direct system calls, no new dependency. Nothing on Linux yet

Not exact equality: after a seek the samples differ in the last bits, and Whisper's casing/punctuation is sensitive to that.

## Moments and clips (milestone 3)

- **Decided 2026-10-20 (user):** sound tags kept as `sounds` for the energy score; the prompt fix (below) in M3; defaults 20–60 s, target 35 s, about one clip per 2 minutes (5–30) (now the Shorts preset; the default became TikTok Rewards, below); the M3 editor shows the 16:9 source (9:16 in M4). Additions: leading fillers ("um", "uh", "you know", "like", "so um") lower the hook and the in point moves past them when the clip stays long enough; a clean ending (punctuation / strong pause) scores, ending mid-thought costs.
- **Platform presets (decided 2026-10-21, user):** the finder's default is **TikTok Rewards: 61–90 s, target 70 s, about one clip per 3 minutes** (TikTok's Creator Rewards pay only for videos over a minute). **Shorts / Reels: 20–60 s, target 35 s, one per 2 minutes.** **Custom:** the user's own lengths (starts from the current ones). `Platform` + `Platform::preset` in `moments.rs` (TS mirror `PLATFORMS` in `clips.ts`); `FinderSettings.platform` is `None` only in projects saved before presets, and `FinderSettings::upgraded` (run in `projects::load`) gives them the preset their lengths match, else Custom. The settings chosen last are remembered in `<app data>/projects/last-finder.json` (`remember_finder`) for new projects; existing projects keep theirs. Under TikTok Rewards, any clip under 61 s (edited or manual) shows "Under 1 minute — not eligible for TikTok rewards" on its card and in the editor. The button opening the settings reads e.g. "TikTok Rewards · 61–90 s".
- **Transcript changes** (`transcribe.rs`, `transcription.rs`): removed sound tags are recorded per segment as `sounds` (whether hidden or shown; a segment of only hidden tags keeps them with empty text). The next part's prompt leaves out the previous part's end when it looks unpunctuated (≥ 12 words and no sentence end or no capital but "I"), so Whisper's lowercase mode doesn't spread; after it, the long fixture's uninterrupted run kept its punctuation (83 of 84 sentence ends).
- **Sentences** (`sentences.rs`, pure): punctuation first (titles never end a sentence; "?", "!", "…" and abbreviations only before a capital: Whisper bleeps swear words as "f!"). Stretches over 20 s / 50 words without a sentence end are cut at pauses scored 1–3 points by length (400 / 700 / 2000 ms, scaled for slow speakers), +1 before a sentence starter, −1 before "and/because…", +2 at a Whisper segment edge, never after "the/to/is…" or before "of/is…" or between numbers; 3 points is a `Pause`. Sentences over 30 s split at their best pause (`WeakPause`). Measured on a real 10-minute talk stripped of punctuation: 0.88 precision, 0.14 recall (2-point pauses were right only half the time, so they don't count). The pause distributions used in the synthetic tests come from that talk (not in the repo); `KREOKIT_TRANSCRIPT=<…/transcript.json> cargo test real_transcript -- --ignored --nocapture` repeats the check, and prints the moments, on any transcript.
- **Moment finder** (`moments.rs`, pure): every run of whole sentences between min and max; score 0–100 = Hook 25 + Start 15 + Ending 15 + Energy 25 + Length 20, each feature 0–1 with its reasons (English phrase lists; for other languages the hook isn't judged and the rest scale up). Energy compares speech rate and the loudness of speech seconds (`loudness.json`) with the video's average, adds laughter/applause in or up to 2 s after the clip, subtracts silences over 2 s. Picking: best first, at most 20% overlap of the shorter clip, avoiding clips already on the board. `Context` precomputes each word's sentence and the speech seconds: two hours take ~0.4 s in a test build. Clip text is filled only for the picked clips.
- **Data:** `project.finder` and `project.clips` (`Clip`: id, in/out, status proposed/kept/discarded, source found/manual, `edited`, latest `moment`). No separate candidates cache: finding is fast. Commands `find_moments(id, settings, finder, avoid, have)`, `score_clips(id, settings, finder, ranges)`, `transcript_text(id, settings)` (spoken words + sentences + sounds), `clip_thumbnail(id, ms)` (`<project>/thumbs/<ms>.jpg`, rounded to 0.1 s, in the asset scope), `waveform_range(id, from, to)` (`waveform.rs` from Captions, reads only that stretch, ≤ 15 min). The video is allowed through the asset protocol when its project opens (`allow_video`).
- **Board** (`ClipsBoard.tsx`, logic in `src/lib/clips.ts`): after a transcript, the project has Clips and Transcript tabs (the Transcribe panel stays mounted so a run survives a tab switch). The finder runs by itself the first time; Find again replaces only untouched proposals (found, proposed, not edited) and rescores the rest; a new transcript rescores every clip. Cards: thumbnail (two FFmpeg runs at a time, `queue.ts`), score, length, range, first line, top reasons; keep / discard / restore, "Why this clip" popover, filter and sort; keys arrows, K, X, U, I, Enter. Add clip; manual clips are deleted rather than discarded.
- **Editor** (`ClipEditor.tsx`, logic in `src/lib/clipEdit.ts`): source video playing in→out, the clip's words with a sentence of context (spoken word highlighted, click seeks, drag-select → Make clip), timeline ported from Captions (`timeline.ts`) with the waveform for the visible window, sentence marks (solid punctuation, dashed pause), in/out handles snapping to sentence edges (2× reach) then word edges, with the finder's padding (150 ms lead, 300 ms tail, at most half the gap). Keys Space, I / O, N, [ / ], K, X, Escape. A trimmed found clip is marked edited.
- **Editor words** are cached per project in memory (`spokenText`) and forgotten when a new transcript arrives (`forgetSpokenText`), so the editor never shows the previous transcript's words and times.
- **Sync report 2026-10-21 (user, Goggins talk, clip 2:38–3:08 made before the presets):** text showed before the words. Measured: that video's audio starts with its picture (no offset), and its Small and Base transcripts both match the speech within 20 ms everywhere (energy-based lag check, validated with a known 500 ms shift); the old clip itself was replaced by Find again, so it couldn't be inspected. Fixed the two mechanisms that do produce early text (late-starting audio; stale editor words), but the user's exact case wasn't reproduced.
- **Tests:** Rust unit tests on synthetic transcripts (the long fixture's script with real-speech pause and segment-edge distributions), the long-fixture test runs the finder on both transcripts and checks whole script sentences; vitest for the board and editor logic.
- **CI runs ignored tests on Linux (FFmpeg 4.4):** a dev-only ignored test must skip (not panic) when its input is missing, and FFmpeg-length checks need some slack (4.4 returned 32 peaks where the dev Mac's FFmpeg gave 31).
